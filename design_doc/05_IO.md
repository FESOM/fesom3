# Input/Output

## Current State

FESOMx currently provides basic I/O functionality for saving and loading grids, fields, and results. The current implementation supports simple formats suitable for development and testing.

**File**: `fesomx/utilities/io_utils.py`

## Supported Formats

| Format | Extension | Use Case | Status |
|--------|-----------|----------|--------|
| Pickle | `.pkl` | Complete grid objects | Implemented |
| NumPy NPZ | `.npz` | Arrays with metadata | Implemented |
| NumPy NPY | `.npy` | Single arrays | Implemented |
| NetCDF | `.nc` | Scientific data (requires xarray) | Basic support |

## Grid I/O

### Saving Grids

```python
from fesomx.utilities.io_utils import save_grid, load_grid

# Save complete grid object (pickle)
save_grid(grid, "my_grid.pkl", format='pickle')

# Save grid data as arrays (npz)
save_grid(grid, "my_grid.npz", format='npz')
```

**Pickle Format**:
- Saves complete grid object including all state
- Best for checkpointing and resuming
- Python version dependent

**NPZ Format**:
- Saves vertices, cells, name, stagger_type
- More portable across Python versions
- Mixed grids require pickle (variable-length cells)

### Loading Grids

```python
# Load from pickle
grid = load_grid("my_grid.pkl", format='pickle')

# Load from npz (returns dict, needs reconstruction)
data = load_grid("my_grid.npz", format='npz')
```

## Field I/O

### Saving Fields

```python
from fesomx.utilities.io_utils import save_field, load_field

# Single array (npy)
save_field(temperature, "temperature.npy", format='npy')

# With metadata (npz)
save_field(temperature, "temperature.npz",
           metadata={'units': 'K', 'time': 0.0},
           format='npz')

# NetCDF (requires xarray)
save_field(temperature, "temperature.nc",
           metadata={'units': 'K'},
           format='nc')
```

### Loading Fields

```python
# Load from npy
temp = load_field("temperature.npy", format='npy')

# Load from npz (returns dict)
data = load_field("temperature.npz", format='npz')
temp = data['data']

# Load from NetCDF
temp = load_field("temperature.nc", format='nc')
```

## Batch Results I/O

For saving multiple fields together:

```python
from fesomx.utilities.io_utils import save_results, load_results

# Save multiple fields
save_results(
    "simulation_output.npz",
    fields={
        'temperature': temp_array,
        'salinity': salt_array,
        'velocity_u': u_array,
        'velocity_v': v_array,
    },
    grid_info={'nx': 64, 'ny': 64, 'stagger': 'C'},
    metadata={'time': 100.0, 'dt': 0.01}
)

# Load results
data = load_results("simulation_output.npz")
```

## Partitioning Utilities

**File**: `fesomx/utilities/partitioning.py`

For distributed grids, partitioning information can be saved/loaded:

### Partitioning Methods

| Method | Library | Description |
|--------|---------|-------------|
| METIS | pymetis | Graph-based, optimal load balance |
| Geometric (RCB) | built-in | Recursive coordinate bisection |
| Geometric (simple) | built-in | Grid-based fallback |

### Usage

```python
from fesomx.utilities.partitioning import (
    partition_triangular_mesh,
    print_partition_summary
)

# Partition triangular mesh
partition, info = partition_triangular_mesh(
    vertices=grid.vertices,
    triangles=grid.cells,
    n_partitions=8,
    method='metis'  # or 'geometric'
)

# Print summary
print_partition_summary(partition, info)
```

### Ghost Cell Mapping

```python
from fesomx.utilities.partitioning import build_ghost_cell_map

# Build ghost cell map for halo exchange
ghost_map = build_ghost_cell_map(
    cell_neighbors=grid.cell_neighbors,
    partition=partition,
    halo_layers=1
)

# ghost_map[0][1] = cells partition 0 needs from partition 1
```

## Limitations

Current I/O is designed for development and testing:

| Limitation | Impact | Planned Solution |
|------------|--------|------------------|
| No Zarr support | Limited cloud/parallel I/O | Add Zarr backend |
| No UGRID convention | Incompatible with UGRID tools | Add UGRID writer |
| Basic NetCDF | No CF conventions | Add CF metadata |
| No parallel I/O | Single-writer bottleneck | Add MPI-IO |
| No compression | Large file sizes | Add compression options |

## Future Extensions

### Planned Formats

| Format | Priority | Use Case |
|--------|----------|----------|
| Zarr | High | Cloud storage, parallel I/O |
| UGRID NetCDF | High | Interoperability with UGRID tools |
| HDF5 | Medium | High-performance, compression |
| VTK | Low | Visualization tools |

### Planned Features

- **CF Conventions**: Standard metadata for climate/ocean data
- **Parallel I/O**: MPI-based collective writes
- **Checkpointing**: Automatic state serialization
- **Streaming**: Write during simulation
