## 3. The scheme (`oce_timestep_RK3_SE`)

The scheme is the three-stage Wicker–Skamarock RK:
- φ\* = φⁿ + Δt/3 F(φⁿ)
- φ\*\* = φⁿ + Δt/2 F(φ\*)
- φⁿ⁺¹ = φⁿ + Δt F(φ\*\*)

It is self-starting: there is no AB history.

| stage | calls, in order | what they do |
|---|---|---|
| 1 (Δt/3) | `vert_vel_RK3(uⁿ)` | Vf (edge flux per level) and Wvel (transport) from uⁿ |
| | `solve_tracers_RK3(1)` | T\* = Tⁿ + Δt/3·A(Tⁿ), advection only |
| | `pressure_RK3(Tⁿ)` | hpressure, no N² |
| | `vel_rhs_RK31_SE` | R = PGF − g∇ηⁿ + Coriolis/metric(uⁿ) + central horizontal + vertical advection, times Δt/3. `U_rhsBC = 3∫R dz` (the depth-integrated rhs at n, times Δt). u\* = uⁿ + R − ⟨R⟩: the barotropic part of the increment is removed. |
| | `bh_viscosity_RK3` | flow-dependent biharmonic from uⁿ, ν = Δt·max(0.05·\|Δu\|, 0.001)·√area, into `U_visc`. Computed once per step and reused in stage 3. |
| | `relax_zonal_vel_RK3_SE` | Soufflet only: adds the U relaxation to `U_visc` |
| | `BC2BT_forcing` | `U_rhsBC += ∫U_visc dz + Δt(τ_s/ρ0 + friction·u_bot)`, with friction hard-coded to −0.005 |
| 2 (Δt/2) | `vert_vel_RK3(u*)`, `solve_tracers_RK3(2)` | T\*\* = Tⁿ + Δt/2·A(T\*) |

| | `vel_rhs_RK3(u*, Δt/2)` | u\*\* = uⁿ + R(u\*) − ⟨R⟩ |
| 3 (Δt) | `pressure_bv_RK3(T**)` | hpressure + N² |
| | `compute_vel_nodes`, `oce_mixing_PP_` | Kv and Av from uⁿ and N²(T\*\*). Soufflet forces Av = 1e-4. |
| | `vert_vel_RK3(u**)` | |
| | `BT_SESM_RK3` | First subtracts the barotropic rhs at n (from etaBT, UBT, VBT) from `U_rhsBC`. **Advection.**
- **Tracers:**
  - Horizontal: MUSCL (`num_ord = 0.05`, i.e. 5 % central blend).
  - Vertical: 4th-order-type, 90 % centred (`num_ord = 0.9`).
  - No FCT or limiter.
  - The elemental gradient is rebuilt and exchanged every stage.
  - FESOM3 already has this MUSCL rule (HANDOFF.md "MUSCL horizontal tracer advection … reference RK3 rule", LESSONS
    L59). The difference: RK3 calls it on the stage tracer, with no `valuesAB`.
- **Momentum:**
  - Horizontal: central flux form with the divergence removed, −Σ(u_e − u_c)·uₙ·l/area.
  - Vertical: centred.
  - FESOM3 production uses vector-invariant advection (`momadv_opt = 1`, rvo_upwind blend). See section 5, item 3.

**Quirks in qq_new2. Do not port them blindly; confirm with Sergey where noted.**
1. `BTsteps = 90` and `aSM = 0.1` are hard-coded in `BT_SESM_RK3` (:285, :291). In the port they become knobs.
2. `friction = -0.005` (Soufflet linear drag) overwrites the C_d drag, in `BC2BT_forcing` :256 and
   `impl_vert_visc_SE_1`. The port uses FESOM3's bottom drag.
3. **`U_rhsBC` is first order.** The comment at :320 says it could be made second order with stored AB2. Ask Sergey.
4. **The stage-3 Coriolis term is `V_rhsAB*(f + m*U_n)`:** the metric part is at n, the rest at n+½ (:420). `qq_new`
   had all of it at n+½. This does not matter on the Cartesian channel; on the sphere, decide.
5. **`eta_n` is already η^{n+1}** when `vel_rhs_RK33_SE` builds −g∇η. This is harmless, because the trim removes any
   depth-uniform force. In the port, make it explicit.
6. **Shared elements:** the RK3_SE path calls no shared-element sync. The comment at :387 says "it would be safer…".
   FESOM3 needs it (section 4).
7. **Soufflet starts at η = 0, which is not balanced**, giving a ~0.7 m seiche under SE (12 Oct analysis).
8. **The CG path has a bug:** `vel_rhs_RK32` (`oce_stepRK3.F90:377`) divides `vb` by H twice. The SE path does not
   use it.

## 4. FESOM3 now and where RK3 plugs in

**`step_oce`** (`src/step/mod_step_oce.F90:83-329`) is the FESOM2-faithful ALE step:
1. `compute_vel_nodes`
2. `pressure_bv`, PGF (`pressure_force_4_linfs_fullcell`, or Shchepetkin under zstar)
3. GM/Redi producers
4. `compute_shear2` + PP/KPP/TKE + `mo_convect`
5. `compute_vel_rhs` (AB2 with `ab_epsilon`; `uv_rhsAB`, `oce_dyn_velrhs.F90`)
6. `viscosity_filter`, `impl_vert_visc_ale`
7. the SSH, by one of two paths:
   - CG: `compute_ssh_rhs_ale`, `solve_ssh_ale`, `update_vel`, `compute_hbar_ale`, `update_eta_n`;
   - **SE** (`FESOM3_SSH_SE=1`): `se_bt_forcing`, `se_subcycle`, `se_trim_finish` in `src/oce/oce_ssh_se.F90`. It is
     the same SM AB3–AM4 core as `BT_SESM_RK3`, plus BT viscosity, BT drag, the D4 Coriolis r-term and zstar
     (`docs/plans/completed/2026-10-17-split-explicit.md`).
8. GM bolus, `vert_vel_ale`
9. `solve_tracers_ale` (AB `valuesAB` via `init_tracers_AB`, `oce_ale_tracer.F90`; FCT/MUSCL kernels in
   `oce_adv_tra_*`)
10. `update_thickness_ale`

**Other points the port must handle:**
- **Call order:** `ice_timestep` runs before `step_oce` (`src/drivers/fesom_lifecycle_native_mr.F90:1055, 1071`). The
  forcing fluxes are computed once per step and stay fixed through the three stages. In qq the surface fluxes enter
  only in stage 3, with the vertical diffusion.
- **Restart:** the restart stores the AB history: `urhs_AB`, `vrhs_AB` (+AB3) and `<tracer>_AB`
  (`src/io/mod_io_restart.F90:355-369`). RK3 needs none of it. It needs only the state (+ the SE state). Decide how an
  RK3 run reads an AB2 restart (ignore the AB fields) and the reverse (cold AB start).
- **Bottom at vertices** (IMPLEMENTATION.md §13, LESSONS L53): qq has FESOM2's bottom on elements. Its `area(nz,node)`
  shrinks with depth and H = −zbar(nlevels(elem)). In FESOM3 the vertex column is authoritative, the elements are the
  min over their corners, and the scalar cell has the full area at every wet layer. Re-derive every H, area and Wvel
  formula: the element H is Σ helem (as SE did). FESOM3 `w` is a velocity; qq's `Wvel` is w·area.
- **Shared elements:** after each velocity update there must be one owner per shared element (`exchange_elem_shared` in
  `update_vel`, `FESOM3_SHARED_SYNC`, `docs/plans/completed/20261012-shared-element-sync.md`). RK3 updates the velocity
  three times per step (u\*, u\*\*, uⁿ⁺¹), and the tracers are advected with each. Without the sync, the linfs
  volume/salt leak of CORE2 results7/11/17/21 comes back.
- **Hybrid tri+quad meshes:** qq's `gradient_sca(1:4)/(5:8)` corresponds to FESOM3's unified 4-slot arrays. Use
  FESOM3's mesh arrays.
- **Cost:** each step runs 3 tracer advections and 3 momentum rhs (qq: stage 3 ≈ half the step). RK3 pays off only
  with a longer Δt. Measure; don't assume.

## 5. Decisions for the brainstorm (ask Dmitry; collect questions for Sergey)

1. **Barotropic solver for v1.**
   - Option A: RK3 + SE as in qq_new2, reusing FESOM3's `se_subcycle` core (BT viscosity and drag) fed by the RK3
     BC→BT forcing.
   - Option B: port `BT_SESM_RK3` as is.
   - The SI/CG RK3 (`oce_timestep_RK3`) is optional, later.
   - Recommendation: A, with the qq settings reproducible: BT visc/drag off, M = 90, aSM = 0.1.
2. **linfs first, as qq does.** zstar later needs per-stage thicknesses (hnode for u\*, u\*\*). Design the hooks now, as
   SE did.
3. **Momentum operators:** port qq's central flux-form advection and `bh_viscosity_RK3` as new options, and/or run
   FESOM3's vinv + `opt_visc` per stage. Either way the operators must take the stage velocity as an argument and must
   not touch `uv_rhsAB`.
4. **Tracer advection under RK3:** qq's MUSCL (0.05) and vertical (0.9) without FCT, or FESOM3's FCT on each stage. FCT
   per stage costs ×3.
5. **Mixing, GM/Redi, KPP/TKE:** compute once per step. qq does it in stage 3 from uⁿ and N²(T\*\*); FESOM3 does it at
   the step start. Which state feeds them?
6. **Ice/forcing:** once per step; surface fluxes and relaxation only in stage 3, with the implicit diffusion.
7. **Knob:** e.g. `FESOM3_TIMESTEP=rk3` (namelist + `FESOM3_*` env override, as `FESOM3_SSH_SE`), plus
   `FESOM3_RK3_BTSTEPS` and `FESOM3_RK3_ASM`, or the existing `FESOM3_SE_*` knobs. Default AB2, byte-identical.
8. **For Sergey:**
   - Stage 2 uses the pressure of T\*\* (tracers updated first). Is that intended, a forward–backward choice for the
     internal waves? Keep it unless he says otherwise.
   - Is the first-order `U_rhsBC` enough?
   - At which time level should the metric term in stage 3 be?
